## High

- [x] **Cancel is ignored while a file is being hashed or the connection is opened** - `SendService.cancelTransfer` only knows sockets that are already in `_activeTransfers`, which are added after `md5OfFile` and `Socket.connect`. `SendQueueController.cancelAll` during the "Preparing..." phase (long for big files) returns `false` from `_cancel`, clears the queue, and then the send goes on and transfers the whole file. Register a cancellation token (flag or `Completer`) at the start of `sendFile` and check it after hashing and after connecting. Add a test for cancelling in the preparing phase.
  - File(s): `lib/services/network/send_service.dart` (lines 29 and 62-65, 267-274), `lib/services/send_queue_controller.dart` (line 121)
- [x] **An avatar that receivers reject is requested and sent again every 30 seconds, forever** - The picker and `ProfileImageStore.import` do not check the limits that the sender and the receivers enforce (10 MB, 4096 px). `_avatarHashFor` still announces the hash, `sendAvatar` refuses oversized files, and receivers fail in `_decodeLimited` for large dimensions, so no avatar is cached and `PeerManager._requestAvatarForPeer` asks again at every `DEFAULT_AVATAR_RETRY_INTERVAL`. Validate (or downscale) the image once in `ProfileImageStore.import`, tell the user, and do not announce a hash for an image that cannot be sent.
  - File(s): `lib/services/profile_image_store.dart`, `lib/services/network_service.dart` (line 183), `lib/services/network/send_service.dart` (line 153), `lib/models/avatars.dart` (line 60), `lib/models/peer_manager.dart` (line 145)
- [x] **The sender shows "File sent successfully" without any answer from the receiver** - The sender closes the socket after `flush` and never learns whether the receiver verified the MD5 and kept the file. A checksum mismatch, a full disk (receiver aborts, see `_writeOrThrow`) or a closed receiver all look like success on the sending side. Add a one byte result frame (OK / FAILED) from the receiver after `end()`, wait for it in `_sendFileWithMetadata` with a timeout, and treat a missing answer from an old receiver as "unknown" so versions stay compatible.
  - File(s): `lib/services/network/send_service.dart` (lines 296-300), `lib/services/network/receive_service.dart` (line 90), `lib/services/send_queue_controller.dart` (line 170)
- [x] **Dropping a folder or a vanished file breaks `addFiles` and can leave the UI stuck** - `SendDropZone` passes `_queue.addFiles` as a `void` callback, so its `Future` is dropped and any `File(path).length()` error (a dropped directory, a file deleted before the call) becomes an unhandled async error. `_isTransferring = true` is already set at that point and is never reset, so the progress card stays visible with an empty queue. Catch per file, skip and report invalid paths (and expand or reject directories), and set the flags only after at least one file was accepted. Also replace `file.path!` in `_pickFiles` with a null check.
  - File(s): `lib/services/send_queue_controller.dart` (lines 98-118), `lib/widgets/send/send_drop_zone.dart` (line 70), `lib/screens/peer_details.dart` (line 55)

## Medium

- [x] **`cancelAll` followed quickly by `addFiles` can fail the wrong file** - `addFiles` resets the shared `_cancelled` flag, so when the cancelled send rejects a moment later, the loop's `catch` no longer sees `_cancelled`, calls `_onFailure` and `_queue.removeFirst()`, which removes the first of the new files. Give every run a generation number (or token) captured by the loop and ignore results of an old generation.
  - File(s): `lib/services/send_queue_controller.dart` (lines 102, 121-135, 172-176)
- [x] **A closed connection while waiting for the ready signal is treated as "proceed anyway"** - On `onDone` and on `onError` `_waitForReadySignal` completes normally, so a receiver that rejected the transfer (size limit, connection limit, add failed) still gets the whole file pushed into a dead socket, and the real error only appears later from `addStream`. Make closure and error fail fast with a clear exception and keep the "proceed" behavior only for the timeout. Also a first chunk shorter than 3 bytes is ignored and costs the full 5 second timeout; buffer until `READY_SIGNAL_LENGTH` bytes.
  - File(s): `lib/services/network/send_service.dart` (lines 180-233)
- [x] **The avatar is hashed again for every send and for every username change** - `_createAvatarMetadata` calls `_createFileMetadata`, which reads the whole file for MD5, although `LocalIdentity.avatarHash` already holds it. A burst of new peers triggers one hash per peer. In addition `HomePage._updateUser` calls `setProfileImagePath` on every saved username, which rehashes an unchanged image. Reuse `identity.avatarHash` in the avatar metadata and call `setProfileImagePath` only when the path changed.
  - File(s): `lib/services/network/send_service.dart` (lines 168-176, 237-257), `lib/services/network_service.dart` (lines 173-181), `lib/screens/home_page.dart` (lines 135-136)
- [x] **Username and avatar have two sources of truth at startup** - `main()` loads the settings, `HomePage._startNetwork` pushes the username with `setUsername`, and then `NetworkService.start()` loads the settings again with its own `SettingsService` and overwrites the identity. `NetworkService` has the dependency only for this. Pass the `User` to `start(user)` (or let `HomePage` set both values) and drop `SettingsService` from `NetworkService`.
  - File(s): `lib/services/network_service.dart` (lines 44, 130, 230-235), `lib/screens/home_page.dart` (line 64), `lib/app_services.dart`
- [x] **IP lookup: one exception skips the fallback, and the first interface wins** - In `_getIpAddress` the `getWifiIP()` call and the `NetworkInterface.list` fallback share one `try`, so a platform where the plugin throws (unsupported desktop, missing permission) returns `null` instead of trying the interfaces. The fallback then takes the first non-loopback IPv4 address, which on Linux and Windows can be a Docker, VM or VPN adapter and not the LAN card. Wrap `getWifiIP` on its own, skip known virtual interface names (`docker`, `veth`, `virbr`, `vboxnet`, `vmnet`, `tun`, `tap`) and prefer private ranges.
  - File(s): `lib/services/network_service.dart` (lines 237-271)
- [x] **`PeerDetailPage` keeps a stale `Peer` snapshot** - The page gets the `Peer` once at navigation time and sends to `widget.peer.address` and `port` for as long as it is open, even if the peer changed its port or name, or left the network 30 seconds ago (the send then fails after `CONNECT_TIMEOUT`). Listen to `peerStream` for the peer id, use the latest value when sending, and show an "offline" state that disables the drop zone.
  - File(s): `lib/screens/peer_details.dart`, `lib/screens/home.dart` (lines 94-103)
- [x] **A received avatar rebuilds the whole peer list and couples `ReceiveService` to `PeerManager`** - `_processReceivedAvatar` ends with `peerManager.notifyPeersUpdated()`, which emits the full list and rebuilds every `ListTile`, although `AvatarStore.listenableFor` was introduced so that only one avatar repaints (`setAvatar` already updates the notifier). Remove the call and the `peerManager` parameter of `ReceiveService` (and then the now unused `notifyPeersUpdated` if nothing else needs it).
  - File(s): `lib/services/network/receive_service.dart` (lines 20, 258-260), `lib/models/peer_manager.dart` (line 93), `lib/services/network_service.dart` (line 94)
- [ ] **`FileTransfer.end` and `closeOnSocketClosure` duplicate the close and verify logic** - Both flush, close, stop the timer, verify the MD5 and delete the file. `closeOnSocketClosure` is only called for incomplete or failed transfers, so its "MD5 matched, keep the file" branch can never produce a useful result (nobody records or announces that file) and ends with three lines of "maybe notify?" comments. Extract a private `_closeSink()` plus `_verifyMd5()`, and make `closeOnSocketClosure` simply close and delete.
  - File(s): `lib/models/file_transfer.dart` (lines 153-230)
- [ ] **`NetworkService` still builds all its collaborators and hosts unrelated logic** - Its constructor creates `PeerManager`, `SendService`, `ReceiveService`, `ServerService`, `IpMonitor` and `DiscoveryService`, so tests cannot substitute any of them, and the class also contains the IP discovery code and avatar hashing. Move `_getIpAddress` to a `LocalIpResolver` class (the `IpResolver` typedef is already there), move `_avatarHashFor` next to `md5OfFile`, and accept the sub-services as optional constructor parameters (as already done for `ipResolver`) or build them in `AppServices.create`.
  - File(s): `lib/services/network_service.dart`, `lib/app_services.dart`
- [ ] **Icon paths depend on the current working directory** - The Linux notification icon is `Directory.current/build/flutter_assets/...`, which exists only when the app runs from the project folder after a build; the Windows tray icon and the window icon fallback use `Directory.current/assets/icons/...`. When the app starts from a shortcut, autostart or an installed bundle the working directory is different and the icons are silently missing. Resolve them from `Platform.resolvedExecutable` (`data/flutter_assets/...`) or use the asset path APIs.
  - File(s): `lib/models/notifications/linux_notification_backend.dart` (line 57), `lib/bootstrap/desktop_shell.dart` (lines 55, 117, 121)
- [ ] **`SettingsScreen` has unhandled failures and bypasses the settings flow** - `_pickImage` awaits `ProfileImageStore.import` (file copy and directory listing) without `try/catch`, so a permission or disk error is an unhandled exception and the UI keeps the old image without a message. `_pickDirectory` changes `FileTransferManager.downloadPath` directly and only then asks `HomePage` to save, so if `saveSettings` fails the running app and the stored setting differ. `onUserUpdated` is typed as the loose `Function(User)`. Catch and report errors, make the user update (not the screen) apply the new download path, and type the callback as `Future<void> Function(User)`.
  - File(s): `lib/screens/settings.dart` (lines 19, 62-100), `lib/screens/home_page.dart` (lines 130-144)

## Low / Nice to have

- [ ] **Unused dependencies, a dead vendored plugin and a wrong SDK constraint** - `filesize` and `cupertino_icons` are not used by any file in `lib/` or `test/`. `packages/flutter_local_notifications/` (about 97 tracked files, Java sources included) is not referenced by `pubspec.yaml` (no `path:` or `dependency_overrides`), so it is dead weight, or a forgotten override. `pubspec.yaml` allows `sdk: '>=3.2.3'` while the code uses `Color.withValues` (Flutter 3.27 / Dart 3.6). Remove what is unused, document or wire the vendored copy, and raise the SDK lower bound.
  - File(s): `pubspec.yaml`, `packages/flutter_local_notifications/`, `lib/widgets/send/transfer_progress_card.dart` (line 41)
- [ ] **Notification channel ids do not match and Linux notifications never expire** - Android creates the channel `file_transfer_channel` in `init` but shows notifications on `woxxy_channel`, so the created channel is unused and the real one is made implicitly. On Linux every "File Received" notification uses `LinuxNotificationUrgency.critical` and `resident: true`; the freedesktop spec says critical notifications do not expire automatically, so they pile up in the shell. Use one shared channel id constant and normal urgency.
  - File(s): `lib/models/notifications/android_notification_backend.dart` (lines 18-47), `lib/models/notifications/linux_notification_backend.dart` (lines 44-48)
- [ ] **`DiscoveryService._disposed` means the opposite of its name and the avatar send is not awaited** - The flag starts `true` ("until start() is called") and is `true` again after `dispose`, so it really is `!_running`; reading `if (_disposed) return` in `restart` takes effort. Rename it to `_running`. In `_handleAvatarRequest` the `Future<bool>` of `sendAvatarCallback` is dropped; use `unawaited(...)` (and `_isRunning` checks) to show that this is intended.
  - File(s): `lib/services/network/discovery_service.dart` (lines 38, 66, 90, 108, 242)
- [ ] **Small dead branches in the UI** - `HomeContent` checks `!snapshot.hasData`, which cannot happen because `PeerManager` uses a seeded `BehaviorSubject`, so the "Searching..." text is never shown (use `peerManager.currentPeers` as `initialData` and a real "searching" state if it is wanted). `HistoryScreen` is a `StatefulWidget` without state. `SettingsScreen._buildProfileImage` has an `.svg` branch, but the picker no longer offers SVG. `SettingsService.saveSettings` has a "remove profile image" branch that cannot run because `User.copyWith` treats `null` as "keep", so a picture can never be cleared.
  - File(s): `lib/screens/home.dart` (line 70), `lib/screens/history.dart` (line 7), `lib/screens/settings.dart` (line 136), `lib/models/user.dart` (line 39), `lib/services/settings_service.dart` (line 25)
- [ ] **Tray and window handling live in `HomePage`'s `State`** - `HomePage` mixes in `TrayListener` and `WindowListener`, repeats the `Platform` check as `_isDesktop` (already `DesktopShell.isDesktop`), and keeps window logic (hide on close, show and focus on tray click) in a screen widget. Move the listeners to a small `DesktopShell` instance created in `main()`, which also removes the `Platform` dependency from the widget tree.
  - File(s): `lib/screens/home_page.dart` (lines 31-127), `lib/bootstrap/desktop_shell.dart`
- [ ] **Send queue: fixed pauses and two booleans for one state** - `SendQueueController` waits `_pauseAfterSuccess` (500 ms) after every file and 1 s after a failure, which adds minutes to a queue of hundreds of small files and has no documented reason now that the receiver sends a ready signal. `QueuedFile` uses `isCompleted` and `isFailed` (four possible combinations for three states) and is mutated from outside. Remove or justify the pauses, and replace the flags with an enum `QueuedFileStatus { waiting, completed, failed }`.
  - File(s): `lib/services/send_queue_controller.dart` (lines 22-32, 68-69, 171, 176)
- [ ] **History can lose the last entry when the app quits** - `autoSave` starts a write on every change but nothing awaits it, and the tray "Quit" runs `AppServices.dispose` and then `exit(0)`. A file received just before quitting may not be saved yet. Keep the `autoSave` stop function and a `flush()` in `HistoryRepository` and await it in `AppServices.dispose`.
  - File(s): `lib/services/history_repository.dart` (lines 36-60), `lib/app_services.dart` (lines 31-35), `lib/main.dart` (line 30)
- [ ] **Local constants and literals break the UPPERCASE rule** - `DesktopShell._setupWindow` uses local `const windowSize`, `minSize`, `maxSize` and inline delays of 100 and 200 ms; `_avatarTempDirectory` uses the literal `'woxxy_avatars'`; the profile picture is shown at `radius: 50` and the history key is built by string concatenation. Move the window sizes, delays and folder name to named uppercase constants in `lib/config/`.
  - File(s): `lib/bootstrap/desktop_shell.dart` (lines 35-37, 74, 131-133), `lib/services/network/receive_service.dart` (line 220)
- [ ] **History speed field is named "upload" for received files** - `FileHistoryEntry.uploadSpeedMBps` is the speed of a download (it comes from `FileTransfer.getSpeedMBps` on the receiver). Rename to `speedMBps` and keep reading the old JSON key in `fromJson` so saved histories still load.
  - File(s): `lib/models/history.dart` (lines 14, 21, 29, 38), `lib/screens/history.dart` (line 73), `lib/services/received_files_handler.dart` (line 44)
